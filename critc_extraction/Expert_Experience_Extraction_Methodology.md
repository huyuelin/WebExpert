# 通用专家经验提取方法论

## 概述

本文档总结了一套通用的专家经验提取方法，基于对信贷审批数据集的成功实践，该方法可以从标注数据中提取和总结专家的批评性经验，并将其转化为可复用的通用规则。

## 方法论架构

### 核心流程图

```
标注数据 → 句子提取 → 语义嵌入 → 主题聚类 → 主题合并 → 经验生成 → 通用规则
    ↓         ↓         ↓         ↓         ↓         ↓         ↓
输入数据   sentence  embedding  clustering  merging  critic   final
         level     vectors    topics     topics   rules    output
```

### 关键步骤详解

#### 1. 数据预处理 - 句子级提取
**文件**: `extract_sentences.ipynb`
**目标**: 从结构化标注数据中提取有效的批评性评价句子

**核心逻辑**:
- 解析结构化输出，提取以"- "开头的条目
- 过滤掉标记为"[无错误]"的内容
- 按标签分类（如"负向"、"正向"等）
- 输出格式: `[{"label": "标签", "item": "句子内容"}, ...]`

**通用化要点**:
- 可适应不同的标注格式（JSON、XML、CSV等）
- 支持自定义过滤规则（如错误标记、无效内容）
- 可扩展到多种标签体系

#### 2. 语义表示 - 嵌入向量生成
**文件**: `extract_embedding.ipynb`
**目标**: 将文本转换为高维语义向量，为聚类做准备

**核心组件**:
- **嵌入模型**: 使用预训练模型（如 Qwen3-Embedding-8B）
- **降维处理**: 
  - t-SNE 用于可视化（降到2维）
  - PCA 用于聚类预处理（降到100维）
- **质量评估**: 
  - 轮廓系数 (Silhouette Score)
  - Calinski-Harabasz 指数
  - Davies-Bouldin 指数

**通用化参数**:
```python
# 可配置参数
EMBEDDING_MODEL = "your-embedding-model"  # 嵌入模型路径
PCA_COMPONENTS = 100                       # PCA降维维度
TSNE_COMPONENTS = 2                        # t-SNE可视化维度
MIN_CLUSTER_SIZE = 20                      # HDBSCAN最小聚类大小
```

#### 3. 主题发现 - 无监督聚类
**文件**: `extract_embedding.ipynb` (BERTopic部分)
**目标**: 将语义相似的句子自动分组成主题

**技术栈**:
- **BERTopic**: 主题建模主框架
- **UMAP**: 非线性降维
- **HDBSCAN**: 基于密度的层次聚类
- **中文分词**: jieba分词处理

**关键配置**:
```python
# BERTopic 配置示例
umap_model = UMAP(n_neighbors=15, n_components=10, min_dist=0.0, metric='cosine')
hdbscan_model = HDBSCAN(min_cluster_size=15, metric='euclidean', cluster_selection_method='eom')
vectorizer_model = CountVectorizer(min_df=10, tokenizer=tokenize_zh)
```

#### 4. 主题标注 - 语义标签生成
**文件**: `topic_generation.py`
**目标**: 为聚类生成的主题分配人类可理解的标签

**核心流程**:
- 批量处理主题内容（批大小=100）
- 使用 LLM 生成主题标签
- 参考预定义主题词库
- 输出格式: `{"主题名": "句子集合"}`

**Prompt 模板**:
```python
prompt_template = """
你是一个{领域}专家，以下是若干条根据{评价维度}的分析结论：
{文本内容}

请你对这些内容归纳出一个主题词，该主题词表达了这些内容的分析方面。
输出格式为\\topic{主题名}
"""
```

#### 5. 主题整合 - 层次合并
**文件**: `merge_topic.ipynb`
**目标**: 将细粒度主题合并成更有意义的大类

**合并策略**:
- 按主题名称分组
- 选择最小编号作为代表
- 合并同类主题下的所有句子
- 生成主题字符串供后续使用

#### 6. 负类处理 - 分类修正
**文件**: `process_negative_class.py`
**目标**: 处理聚类算法无法正确分类的"负类"样本

**重分类流程**:
- 提取标记为"负类"的句子
- 使用 LLM 重新分类到预定义类别
- 将重分类结果合并到对应主题
- 删除原始"负类"标签

#### 7. 经验提炼 - 规则生成
**文件**: `critic_generation.py`
**目标**: 将同类经验合并成通用的批评规则

**提炼原则**:
- 合并表述内容高度重复的经验
- 用区间或范围表达参数变化规则
- 保留实质差异的判定角度
- 每个类目限制最多10条经验
- 使用简洁语言表述

**Prompt 核心**:
```python
prompt_template = """
以下是关于「{主题}」的多条错误经验，输出合并同类错误经验后的所有经验：

## 注意
- 将表述内容高度重复、参数范围或数值不同但思路一致的内容合并
- 用"区间"或"范围"表达综合性规则，避免冗余
- 每个类目下最多10条经验
- 用尽量简洁的语言表述

## 经验
{经验内容}

## 输出格式
{{"{主题}":["经验1","经验2"...]}}
"""
```

## 质量控制指标

### 聚类质量评估
- **轮廓系数**: > 0.5 为良好
- **CH指数**: 越大越好，通常 > 1000
- **DB指数**: < 1.0 为良好

### 主题质量评估
- **主题数量**: 建议 30-60 个主题
- **主题覆盖率**: > 95% 的句子被分配到非噪声主题
- **主题一致性**: 同主题内句子语义相关性 > 0.7

### 经验质量评估
- **合并率**: 每个主题平均合并比例 > 50%
- **规则数量**: 每主题 3-10 条规则
- **覆盖度**: 原始句子信息保留度 > 80%

## 适用领域扩展

### 通用数据集适配指南

#### GAIA (General AI Assistant) 数据集
- **特点**: 多轮对话，复杂推理任务
- **适配要点**:
  - 提取推理错误模式
  - 关注多步骤推理链
  - 主题可能包括：逻辑推理、信息检索、知识整合等

#### HLE (Human-Like Evaluation) 数据集  
- **特点**: 人类评价标准，主观性较强
- **适配要点**:
  - 提取评价偏好模式
  - 关注主观判断标准
  - 主题可能包括：语言质量、逻辑一致性、事实准确性等

#### PQA (Product Quality Assessment) 数据集
- **特点**: 产品质量评估，结构化程度高
- **适配要点**:
  - 提取质量判断标准
  - 关注缺陷模式识别
  - 主题可能包括：功能性问题、性能问题、用户体验等

#### WebWalkerQA 数据集
- **特点**: 网页浏览和问答，动态交互
- **适配要点**:
  - 提取导航错误模式
  - 关注信息提取准确性
  - 主题可能包括：页面理解、信息定位、操作执行等

### 领域适配配置

```python
# 领域特定配置示例
DOMAIN_CONFIG = {
    'GAIA': {
        'min_cluster_size': 10,      # 推理模式可能更分散

        'embedding_model': 'reasoning-focused-model'
    },
    'HLE': {
        'min_cluster_size': 15,      # 评价标准相对集中
        'topics_range': (20, 40),    # 评价维度相对固定
        'embedding_model': 'evaluation-focused-model'
    },
    'PQA': {
        'min_cluster_size': 20,      # 质量问题类型明确
        'topics_range': (30, 50),    # 质量维度结构化
        'embedding_model': 'quality-focused-model'
    },
    'WebWalkerQA': {
        'min_cluster_size': 12,      # 操作模式多样但有限
        'topics_range': (25, 45),    # 网页操作类型适中
        'embedding_model': 'action-focused-model'
    }
}
```

## 实施建议

### 阶段性实施路径

#### 第一阶段：基础流程搭建（1-2周）
1. 环境配置和依赖安装
2. 数据预处理模块开发
3. 基础聚类流程验证

#### 第二阶段：核心算法优化（2-3周）
1. 嵌入模型选择和调优
2. 聚类参数精调
3. 质量评估体系建立

#### 第三阶段：经验提炼完善（1-2周）
1. LLM 提示工程优化
2. 主题合并策略优化
3. 输出格式标准化

#### 第四阶段：领域扩展验证（2-4周）
1. 目标领域数据适配
2. 领域特定参数调优
3. 效果评估和迭代优化

### 关键成功因素

1. **数据质量**: 确保标注数据的准确性和完整性
2. **模型选择**: 选择适合领域的嵌入模型
3. **参数调优**: 根据数据特点调整聚类参数
4. **人工校验**: 定期人工检查主题和规则质量
5. **迭代优化**: 基于实际效果持续改进流程

### 潜在风险与对策

| 风险类型 | 具体风险 | 对策措施 |
|---------|----------|----------|
| 数据风险 | 标注不一致、噪声数据 | 数据清洗、多轮校验 |
| 技术风险 | 聚类效果差、主题重叠 | 参数调优、算法改进 |
| 质量风险 | 规则过于具体或泛化 | 人工审核、专家评估 |
| 扩展风险 | 领域适配困难 | 逐步迁移、小批试验 |

## 总结

本方法论提供了一套完整的专家经验提取框架，核心优势包括：

1. **自动化程度高**: 大部分流程可自动执行
2. **可解释性强**: 聚类和规则生成过程透明
3. **扩展性好**: 可适配不同领域和数据类型
4. **质量可控**: 多层次质量评估机制

通过合理的参数配置和领域适配，该方法可以有效应用于 GAIA、HLE、PQA、WebWalkerQA 等多种数据集，为不同领域的专家经验提取提供统一的技术方案。
